## 2. Method and Evidence Limits

Evidence labels used here:

- **[Observed—reference]** supplied design-reference screenshot/token/note.
- **[Observed—rendered]** local browser/audit snapshot or screenshot from the supplied parent audit context.
- **[Observed—source]** current local implementation source. Existing dirty source may contain user changes; it is read-only evidence and not attributed to this audit.
- **[Inferred]** interpretation grounded in listed observations, not a confirmed requirement.
- **[Needs Verification]** unresolved question with uncertainty qualifier.

Evidence was inspected in bounded passes across the existing target-design notes, source components, and `.playwright-mcp/` captures. Rendered evidence includes Home desktop, High Scores/dialog and confirmation states, gameplay default/result states, and local mobile render observations. The gameplay mobile pass used effective viewport **500×844**; general responsive captures include **375×812** where applicable. These are local rendered observations only, not supplied design references. Desktop reference screenshots alone carry visual target authority.

Limitations: no new browser interaction or runtime testing was performed for this artifact; no formal accessibility tool or assistive-technology audit was performed. Impeccable critique is **degraded supplementary evidence**: its CLI was unavailable in the audit context, so it is not primary authority and no tool-generated score/findings are claimed. No external design conventions were used to fill project gaps. This analysis does not claim WCAG conformance or non-conformance.

## 5. Classic / Time Attack Findings

- **G-01 | Strength | Low | [Observed—reference + rendered]** Both modes retain a shared comparison-board grammar: current and next cards, center divider/OR treatment, mode status, and paired Higher/Lower choices. Rendered evidence presents the choices as broad, stacked buttons with text labels and directional glyphs. Sources: [`design-reference/notes/design-inventory.md`](../design-reference/notes/design-inventory.md:52), [`components/game/ComparisonBoard.tsx`](../components/game/ComparisonBoard.tsx:1), [`components/game/DecisionControls.tsx`](../components/game/DecisionControls.tsx:10), [`.playwright-mcp/page-2026-10-15T09-54-54-094Z.yml`](../.playwright-mcp/page-2026-10-15T09-54-54-094Z.yml:13).
- **G-02 | Strength | Low | [Observed—source + rendered]** Result feedback is text-labeled (“Correct”, “Incorrect”, or Time Attack’s time delta) and is accompanied by tint/visual feedback; it is not color-only in source. Sources: [`components/game/ClassicGame.tsx`](../components/game/ClassicGame.tsx:203), [`components/game/TimeAttackGame.tsx`](../components/game/TimeAttackGame.tsx:348), [`.playwright-mcp/page-2026-10-15T09-55-19-982Z.yml`](../.playwright-mcp/page-2026-10-15T09-55-19-982Z.yml:16).
- **G-03 | Concern | Moderate | [Observed—source]** Both gameplay modes attach global `h`/`l` and arrow-key handlers. The source shown does not scope these shortcuts to a non-editable context or document visible shortcut guidance. Potential conflicts with keyboard use elsewhere are an inference, not a demonstrated failure. Sources: [`components/game/ClassicGame.tsx`](../components/game/ClassicGame.tsx:157), [`components/game/TimeAttackGame.tsx`](../components/game/TimeAttackGame.tsx:249). **Needs Verification [inferred-from-codebase]:** test keyboard behavior while focus is on interactive controls and inspect discoverability of shortcuts.
- **G-04 | Concern | Moderate | [Observed—source + rendered]** Gameplay shells center the category/mode title between an absolutely positioned back link and status region. The source limits title width and status width; mobile snapshots at effective 500×844 show title, score, and timer/status compressed into a single header. This is a local mobile implementation observation, not a Figma-approved arrangement. Sources: [`components/game/GameplayShell.tsx`](../components/game/GameplayShell.tsx:27), [`.playwright-mcp/page-2026-10-15T09-55-19-982Z.yml`](../.playwright-mcp/page-2026-10-15T09-55-19-982Z.yml:1). **Needs Verification [environment-specific]:** inspect the corresponding visual capture at 500×844, especially long category labels and status collisions.

These mode-specific timing/feedback behaviors are product mechanics, not visual audit license to normalize. Sources: [`components/game/ClassicGame.tsx`](../components/game/ClassicGame.tsx:92), [`components/game/TimeAttackGame.tsx`](../components/game/TimeAttackGame.tsx:47).
- **G-06 | Concern | Moderate | [Observed—reference + source]** Supplied references cover default decisions but not reveal, end-of-run, restart, loading/error, or focus/pressed/disabled states. ## 9. Executive Analysis Gate

### Strongest findings

1. **The core identity is coherent and recognizable** (H-01, G-01): preserve target typography, dark-grid composition, offset accents, and the two-card comparison grammar.
2. **Core decisions are represented with native semantic controls and readable result labels** (H-02, G-02, A-01/A-02), but source/snapshot evidence is not an accessibility conformance audit.
3. **Biggest evidence gap is state design, not the default screens** (DA-03, G-06, I-06): focus/hover/pressed states, game over/restart, errors, and Time Attack urgency lack supplied visual authority.
4. **Responsive risk is concentrated in constrained gameplay/header and dialog layouts** (G-04, I-02): local mobile rendering exists, but it is not a designed target and only the documented effective viewport/capture sizes should be cited.
5. **Keyboard and custom game-over dialog behavior merit focused verification** (G-03, A-03/A-04), with no failure asserted absent interaction/assistive-technology evidence.

### Owner decisions / unresolved Needs Verification

- **[product-decision]** Confirm whether Home theme control is intended to be active and what selected-mode/Go states should communicate; supplied references leave these open (H-04).
- **[product-decision]** Confirm the target treatment for gameplay reveal/game-over/restart, loading/error, Time Attack urgency/timer expiry, and interaction states (G-06, I-06).
- **[inferred-from-codebase]** Verify keyboard shortcut focus interactions and custom game-over focus lifecycle before treating them as defects (G-03, A-04).
- **[capability-unavailable]** Assistive-technology/formal accessibility testing was not performed; no WCAG claim is supported (A-03/A-05/A-06).
- **[environment-specific]** Validate narrow responsive header/dialog behavior against the actual captures/runtime at stated viewports; mobile observations remain implementation evidence only (G-04, I-02).
- **[environment-specific]** No reduced-motion runtime emulation was performed for this analysis (I-05).

### Analysis gate

**Evidence suffices to enter Design: Yes, boundedly.** The supplied desktop reference set and token/source maps are sufficient to design within the confirmed Home and default Classic/Time Attack visual language. They are not sufficient to finalize unspecified states, claim mobile approval, make accessibility conformance claims, or choose unresolved product behavior. Any Design phase should retain the open items above as explicit owner decisions/derived-state questions and keep this audit itself read-only.
